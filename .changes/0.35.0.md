## 0.35.0 - 2026-09-24
### Added
* data-request guardrails: render datetime bounds as ISO 8601 with time (YYYYMMDD only at midnight), since DATETIME parses YYYY-MM-DD by login language
* sqlreview move --slug OLD_SLUG NEW_PATH rebinds legacy reviews whose slug no current path derives; slug warns about them
* sqlreview status --verbose names why a review is invalid or missing (e.g. legacy slug binding mismatch, missing sql_path target)
* Scope records the SQL SHA its framing was confirmed against; publish refuses it after a mid-interview SQL edit until intent, inputs, outputs are re-put
* sqlreview lint flags confirmed items whose text or rationale still reads as provisional; bootstrap re-puts them before publish
* sqlreview carryover lists review draft items that match confirmed scope items on unchanged SQL (whole file or the item's lines)
* data-request publish carries an unchanged scope/review item's confirmation across a revision bump when its text, rationale and governed SQL lines are unchanged
* sqlreview status reports missing bundled templates with the init --apply fix (missing_templates in --json, one stderr line otherwise)
* sqlreview.sh carryforward lists which draft items keep their earlier confirmation; publish --reconfirm-all forces a full re-walk
* sqlreview.sh move PATH PATH migrates a legacy-escaped review slug to the readable one without marking the review stale
* sqlreview.sh status --verbose flags legacy-escaped slugs with the migrate command (migrate= field, JSON migrate key)
* data-request:triage orders the service-desk queue read-only: enquiry numbers resolve to approval-ID repos, with paste-ready comments; co-development delegates agreed tasks by capability
* data-request:amend classifies an analyst amendment to a released extract against query-builder's boundary; engineer-required changes get a paste-ready hand-off and no edit
* data-request:amend eval cases cover a rename, a reorder, an added ICD code, a derived column, a new data element and a generated-SQL hand edit
* Six data-request triage eval cases with Python and Node grader fixture tests: read-only triage, enquiry resolution, screening-only approval, resume, delegation
* data-request analyse seeds header assumptions/limitations as candidates for human confirmation and flags header/review mismatches
* data-request draft, fix and lift prescribe record_assumption/record_limitation at the point of logic (query-builder 0.6.0+)
* sqlreview.sh notes parses the query-builder 0.6.0 analysis-notes SQL header into JSON; --against matches its items to a review
### Changed
* data-request review slugs keep _ and . readable (sql__cohort_pipeline__x); reviews under the old escaped slugs still validate and work
* data-request:fix and :validate route change requests and analyst amendments to data-request:amend
* lychee config skips links to the private nq-rdl query-builder, documentation and data-analysis-scaffold repositories
### Removed
* Remove the root `CLAUDE.md` symlink; `AGENTS.md` is now the only agent context file.
### Fixed
* data-request bootstrap shows each item's rationale with its text when asking for confirmation
* data-request analyse offers one bulk carry-over for scope items bootstrap already confirmed instead of re-walking each
* sqlreview render installs a missing bundled template (e.g. lifts.md in older projects) without overwriting, so silent lift capture no longer stops
