## 0.13.0 - 2026-06-23
### Added
* Curated a set of external Claude Code marketplaces in `.claude/settings.json` (`extraKnownMarketplaces`, all auto-update): newly added worktrunk, MotherDuck, Astral (ruff/uv/ty), JetBrains modern-go-guidelines, and Svelte, and flipped the pre-existing OpenAI Codex entry to auto-update. Also enabled Anthropic's `pr-review-toolkit` from the auto-available official marketplace. Documented in docs/external-marketplaces.md.
* `Claude Code on the web` support — `.claude/settings.json` declares the `codex` + `superpowers` plugins, and a SessionStart hook provisions `gh`, `codex`, `lefthook`, and `changie` for cloud sessions
* `generate_manifests.py` now emits a `::warning::` for any unrecognized top-level key in `registry/marketplace.yaml` (a stale `external:` block, or a typo such as `oder:`), so a misconfigured registry surfaces in CI instead of being silently ignored. Mirrors the existing never-silently-drop policy in `_ordered_local`.
* Docker daemon management for Claude Code on the web — `web-bootstrap.local.sh` starts `dockerd` under the remote gate (the web runner ships docker but no running daemon), with the pattern and rationale documented in the `cc-web-setup` skill
### Changed
* `Claude Code on the web` / local dev: consolidate the web bootstrap into a single `.claude/scripts/install-deps.sh` engine with one ergonomic entrypoint, `make install-deps`. Three modes from one script: `make install-deps` provisions the local dev toolchain (lefthook, changie, gopls, python/jq) for human contributors; `CLAUDE_CODE_REMOTE=true make install-deps` (the documented Setup-script field) additionally pre-seeds the declared plugins into the snapshot BEFORE Claude enumerates skills — the only way `/<plugin>:<skill>` commands appear on the first web session; and `install-deps.sh --session` (the SessionStart hook) self-heals on resumes. Moves `.claude/hooks/{web-bootstrap,web-bootstrap.local,announce-capabilities}.sh` to `.claude/scripts/install-deps{,.local}.sh` + `announce-capabilities.sh`, adds a root Makefile, and documents the mechanism in CONTRIBUTING.md (correcting the disproven "the platform installs enabledPlugins at session start" claim)
* `cc-web-setup` / `claude-code:web-setup` skill: re-scope to teach the verified Claude Code web mechanism (issue #161). Claude Code on the web registers `extraKnownMarketplaces` but does NOT install `enabledPlugins`, so the skill now ships a portable `.claude/scripts/install-deps.sh` engine (exposed as `make install-deps`) that installs the declared set itself, documents the pre-snapshot Setup-script field (`CLAUDE_CODE_REMOTE=true make install-deps`) as the only first-session path, the `--session` SessionStart self-heal for resumes, and the `announce-capabilities.sh` "declared ≠ installed ≠ surfaced" canary. Removes the disproven pre-snapshot `cc-web-setup.sh` plugin pre-seed + `make cc-web-setup` apparatus and the "the platform installs plugins at session start" framing; adds the anti-pattern note (no self-referential meta-marketplace in its own dev env) and scopes the Setup-script/`*.local.sh` seam to non-plugin provisioning (Docker, heavy deps)
* `Claude Code on the web`: plugins are installed DECLARATIVELY by the platform at session start from the marketplace declared in `.claude/settings.json` (per the web docs' "what carries over" table) — so remove the overbuilt install machinery added in #162: the root `Makefile`/`make install-deps` Setup-script entrypoint, the three-mode engine, and every "the platform does not install enabledPlugins" claim. `install-deps.sh` is now a plain `CLAUDE_CODE_REMOTE`-gated SessionStart hook that provisions only non-plugin tooling (gh/codex CLIs, the project dev toolchain + Docker via `install-deps.local.sh`) plus a cheap idempotent `ensure_plugins` SELF-HEAL for the docs' "requires network access to reach the marketplace source" failure mode. The `cc-web-setup` skill, CONTRIBUTING.md, and announce-capabilities.sh are re-scoped to the declarative model; no Setup-script field and no manual per-environment step are required
* Claude Code on the web setup: enable the `pr-review-toolkit` and `gopls-lsp` plugins from the official marketplace in `.claude/settings.json`, and provision `gopls` (the Go language server) via the SessionStart bootstrap hook for cloud sessions
### Removed
* Removed the `external:` marketplace passthrough mechanism (and the worktrunk passthrough entry). External plugins are no longer re-hosted in the `rdl` marketplace; they are consumed from their upstream marketplaces, registered for the team in `.claude/settings.json` via `extraKnownMarketplaces`. See docs/external-marketplaces.md.
### Fixed
* `Claude Code on the web`: install the declared `enabledPlugins` from `web-bootstrap.sh` (new `ensure_plugins`), reading the set straight from `.claude/settings.json`. The platform registers `extraKnownMarketplaces` at session start but does NOT install the enabled plugins from them (verified live on 2.1.185) — so after #160 removed the install machinery, a fresh cloud env had every marketplace registered yet zero plugins installed and no `/<plugin>:<skill>` commands. The install is idempotent (skips plugins already in `claude plugin list`) and non-fatal. `announce-capabilities.sh` now surfaces a one-time "web setup active — commit, plugins appear next session" note when a plugin was freshly installed, and its stale "platform installs plugins at session start" comments are corrected
* `.devcontainer`: drop podman-only `runArgs` (`--userns=keep-id`, `--security-opt=label=disable`) so `devcontainer up` starts under Docker as well as podman. Bind-mount uid alignment now relies on Dev Containers' `updateRemoteUserUID` (the container `node` user is synced to the host uid on start) instead of assuming the host runs as uid 1000; rootless podman users can re-add `--userns=keep-id`. `--cap-add=NET_ADMIN`/`NET_RAW` (needed by `init-firewall.sh`) are retained
* `cc-web-setup` skill: create the `web-bootstrap.sh` SessionStart log via `mktemp` under `umask 077` instead of a fixed `/tmp/rdl-web-bootstrap.log`, closing a symlink-truncation and concurrent-session race window on shared hosts
* `.claude/settings.json`: register the `claude-plugins-official` marketplace in `extraKnownMarketplaces` so the enabled `superpowers`, `gopls-lsp`, and `pr-review-toolkit` plugins resolve and install on Claude Code (web) — previously only `openai-codex` was declared, so those plugins' slash-commands/skills (e.g. `/test-driven-development`) never appeared
* `Claude Code on the web`: scope `.claude/settings.json` to **external dev-helper plugins** (`superpowers`, `gopls-lsp`, `pr-review-toolkit`, `codex`, `modern-go-guidelines`, `astral`, `worktrunk`) and their marketplaces, and remove the self-referential `rdl` marketplace + `rdl@rdl` meta-plugin from the web set — a session for developing this catalog should not install the catalog. Declared plugins install at session start from their (reachable) marketplace, so their `/<plugin>:<skill>` commands surface on the first session, the same path that gives dataops its `/superpowers:*` (no setup script / `make` required)
* `announce-capabilities.sh`: report **installed** plugins (cross-checked against `claude plugin list`), not merely the declared `enabledPlugins` from `settings.json` — verified-installed plugins show under "Enabled plugins (installed)", while any declared-but-not-installed plugin is now flagged with the `make cc-web-setup` remedy instead of being silently announced as present (falls back to the declared set when the `claude` CLI is unavailable)
* `cc-web-setup`: the `ensure_plugins` self-heal now refreshes the marketplace index (`claude plugin marketplace update <marketplace>`) and retries once when a `claude plugin install` fails — recovering the common cold-VM case where the marketplace is registered but its local index is stale (`claude plugin install` reports "Plugin not found in marketplace … your local copy may be out of date" and does not refresh the index itself). Previously the retry re-ran the same failing install against the same stale index and could not recover; the set only installed once the platform refreshed the index on a later session. The "Declared but NOT installed" note in `announce-capabilities.sh` and the self-heal warning now name the stale-index cause, not just an unreachable source. Adds `ensure_plugins` coverage (healthy-index, stale-index recovery, already-present no-op, unreachable) to `test-install-deps.sh`.

## 0.12.0 - 2026-06-22
### Added
* `asctl`, the agentskills.io spec validator (Go CLI under `tools/asctl/`), imported from the former `nq-rdl/agent-skills` repo. CI now validates every skill under `skills/` with `asctl repo-check` via a new `validate-skills` job.
* `claude-code:web-setup` — the `cc-web-setup` skill that bootstraps a repository for Claude Code on the web (provisions `.claude/`, the `web-bootstrap.sh` SessionStart hook, and pre-seeds the RDL marketplace). Recovered from the stranded v0.10.0 sync branch (issue #121, never merged because the sync PR failed to open) and mapped into the `claude-code` plugin.
* asctl repo-check now enforces the skill directory-structure standard: allowed subdirs, rst-only references, and no in-skill agents
* Local pre-commit and pre-push hooks via lefthook mirroring CI; retired the dead .githooks and pre-commit-framework config
* Restored CI workflows: SkillSpector security scan, changelog-fragment gate, and lychee link check; migrated tools/skillspector/scan.sh
### Changed
* Skills under `skills/` are now canonical content authored directly in this repo — the `nq-rdl/agent-skills` source-of-truth repo has been merged in. The previous "vendored from upstream, do not edit" model is retired; edit skills here.
* Normalized skill directories to scripts/references/assets and promoted jules-orchestrator to a top-level bundled agent
### Removed
* The cross-repo skills-vendoring sync (`.github/workflows/sync-skills.yml` and `scripts/sync_pr_body.py`) — the non-atomic `repository_dispatch` handoff behind the issue #121 / PR #122 failures. Skills are edited directly now; `scripts/sync-plugins.sh` still regenerates the plugin trees from `skills/` and `agents/`.
### Fixed
* `/report-skill-issue` now files bug reports to this repository: every skill's `metadata.repo` was repointed from the archived `nq-rdl/agent-skills` to `nq-rdl/agent-extensions` (44 canonical skills + their plugin copies). Because the skill files each report to the *target* skill's `repo` field, leaving the others stale would have misrouted reports to the dead upstream. Adds `tests/test_skill_repo_metadata.py` as a regression guard. (#133)
* Uploads SkillSpector findings at SARIF `note` level — keeps them informational so the code-scanning check no longer gates PRs (#139)
### Security
* Set least-privilege permissions on the triage and slack-review workflows (CodeQL actions/missing-workflow-permissions)

## 0.9.0 - 2026-06-05
### Added
* New `openai-codex` marketplace auto-installs the `codex` plugin — Codex delegation and code review from Claude Code (#90)
* New `rust` plugin exposing the `rust-explain` skill as `/rust:explain` — a tutor for reading, navigating, and sanity-checking unfamiliar Rust code (lifetimes, traits, `unsafe`, numeric crates). Synced from agent-skills@v0.9.0.
* Add `lucid` plugin wiring the hosted Lucid MCP server (Lucidchart / Lucidspark) over Streamable HTTP — installable standalone via `/plugin`, authenticated with OAuth (no API key)
* Skill bundles can now group members under a subject plugin via an explicit `{source, leaf}` mapping (e.g. `{source: go-gh, leaf: gh}` → `go:gh`): `sync-plugins.sh` copies the flat upstream `skills/<source>/` into `plugins/<pluginName>/skills/<leaf>/`, renaming to the leaf so Claude Code invokes `<plugin>:<leaf>`. Grouping is owned in the registry, so the upstream `agent-skills` tree stays flat. Flat string members are unchanged (verified no-diff). New `scripts/check_grouping.py` enforces the contract (valid member shape, unique pluginName, no duplicate leaf). Part of the subject-grouping migration (#102).
* New `rdl` meta-plugin: `claude plugin install rdl@rdl` installs every subject plugin in one command (it declares each as a same-marketplace dependency), and `claude plugin uninstall rdl --prune` removes the set plus orphaned dependencies. Part of #101.
* `plugin.json` and `marketplace.json` are now generated from the registry (`registry/bundles/*.yaml` + `registry/marketplace.yaml` + `VERSION`) by `scripts/generate_manifests.py`, with a `--check` CI gate that fails on drift — the structural fix for #100 metadata rot. Release versioning now flows from a single `VERSION` file.
* Generate `docs/bundles.md` from the registry and flag synced-but-unmapped skills in the sync PR body
* Publish 9 previously-unmapped skills as subject plugins: obsidian (bases/cli/markdown), argo-cd, bitwarden, defuddle, zod, conventional-commits, pre-commit
### Changed
* Updates marketplace owner and `pyproject.toml` author email to the `tsv-datalab@health.qld.gov.au` team address — replaces a personal contact
* Regroup all plugins by subject — skills invoke as `/<subject>:<facet>`; retire the swe/infra/informatics/dev-tools/meta domain bundles (#101, #102)
### Removed
* Retired the `dataops` bundle — its six skills (csv, xlsx, pdf, docx, canvas-design, duckdb) were removed upstream in agent-skills@v0.9.0 — and trimmed `dispatch`/`opencode` from `dev-tools` and `tdd`/`tdd-team-workflow` from `swe`. Reconciles the registry, marketplace, plugin trees, and docs so `validate-bundles` is green again (#100).
* Removed two stale docs pages — `docs/claude.md` (superseded by `docs/ARCHITECTURE.md`; it still described the pre-#83 symlink/submodule model) and `docs/tdd-workflow-review.md` (a review of the `tdd-team-workflow` skill retired in #100).
* Removes the stale `docs/superpowers` plan doc — the grouping mechanism it described already shipped in #108
### Fixed
* Hardened the agent-skills sync pipeline so issue #100-class drift cannot merge unnoticed. Sync PRs are now opened via a GitHub App token so `validate.yml` actually runs on them (bot-token PRs previously received zero CI); the PR body is a concise added/removed/modified summary with a drift callout instead of a 60k-line diff dump; change detection uses `git status --porcelain` so additions-only syncs are not skipped; `sync-plugins.sh` prunes stale plugin copies of upstream-removed skills; `validate-plugins.sh` now validates skill references and plugin copies; and a new `check_consistency.py` enforces registry↔marketplace↔plugins agreement. Pipeline logic is extracted into unit-tested scripts (`tests/`).
* Reconciled `lucid` manifest drift surfaced by manifest generation: the marketplace and plugin descriptions are unified to the single registry value and the stale `0.6.0` version is corrected to `0.8.0` (#100).
* Make the release workflow idempotent — tolerate a changelog batched ahead of the tag (pre-batched release PRs) instead of failing the "nothing to release" guard or double-batching (#111)
