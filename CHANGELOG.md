## 0.17.0 - 2026-06-28
### Removed
* Remove the `ensure_plugins` plugin self-heal (and its `register_marketplace_via_tarball` helper) from the cc-web-setup `install-deps.sh` SessionStart hook. A SessionStart plugin install lands in the plugin cache that `reloadSkills` does not re-scan — so it could never surface a plugin the same session — and `claude plugin install` inside a hook can hang web sessions (anthropics/claude-code#18088). `install-deps.sh` now provisions only the gh/Codex CLIs and the project dev toolchain; first-session skill availability comes from vendoring into `.claude/`, with declarative `enabledPlugins` remaining the best-effort plugin layer.
### Fixed
* cc-web-setup: stop `/claude-code:web-setup` (and the `marketplace-scout` agent) from generating non-existent plugin ids — an id whose `@marketplace` is real but whose plugin name does not exist (e.g. a guessed `pyright-lsp@claude-plugins-official` or `<lang>-lsp`), which passed the `cover`/`ensure` suffix guards and then sat in `.claude/settings.json` as "Declared but NOT installed" forever (failure mode #5, dataops#169). Adds a `web-settings.sh verify` subcommand that fetches each marketplace catalog and flags enabled ids absent from it (distinguishing a genuinely non-existent id from an unreachable-marketplace one, the git-403 case), a `web-setup-plugin-check` PostToolUse hook in the `claude-code` plugin that runs `verify` whenever `.claude/settings.json` is written during a setup session, and a `marketplace-scout` no-guessing rule (never recommend an id not read from a fetched catalog or the curated `marketplaces.json`). Wires `verify` into SKILL.md Phase 2/4 and documents the failure mode in references/web-setup.rst.
* Rework the cc-web-setup skill (`/claude-code:web-setup`) so Claude Code on the web sessions have the team's skills and slash-commands available on the FIRST session. Vendoring skills/agents into `.claude/` (part of the repo clone, enumerated before any network step) is the single first-session route. Declarative `enabledPlugins` is documented as best-effort config for plugins that ship real behavior (hooks/MCP/LSP): its web activation is unverified — external marketplaces 403 over the in-sandbox git proxy, the install races skill enumeration (anthropics/claude-code#63028), and the sandbox is ephemeral — so it is not a first-session guarantee. An advanced HTTPS-fetch escape hatch (documented, no shipped script) covers the rare skill a team cannot commit.
* Fix the cc-web-setup `announce-capabilities.sh` plugin canary, which scraped the human `claude plugin list` table for a `> ` bullet — but the CLI emits a non-ASCII `❯`, so every enabled plugin was misreported as "Declared but NOT installed" even when 80+ were installed. It now parses `claude plugin list --json` (selecting `enabled == true`) and distinguishes installed/enabled from "install unverified" (CLI missing, erroring, or emitting non-JSON), so a genuine failed install is never masked and a healthy one is never mislabeled. The banner no longer implies an installed plugin's skills/hooks are active in the first web session (anthropics/claude-code#63028).

Three modes from one script: `make install-deps` provisions the local dev toolchain (lefthook, changie, gopls, python/jq) for human contributors; `CLAUDE_CODE_REMOTE=true make install-deps` (the documented Setup-script field) additionally pre-seeds the declared plugins into the snapshot BEFORE Claude enumerates skills — the only way `/<plugin>:<skill>` commands appear on the first web session; and `install-deps.sh --session` (the SessionStart hook) self-heals on resumes. * `cc-web-setup` / `claude-code:web-setup` skill: re-scope to teach the verified Claude Code web mechanism (issue #161). Claude Code on the web registers `extraKnownMarketplaces` but does NOT install `enabledPlugins`, so the skill now ships a portable `.claude/scripts/install-deps.sh` engine (exposed as `make install-deps`) that installs the declared set itself, documents the pre-snapshot Setup-script field (`CLAUDE_CODE_REMOTE=true make install-deps`) as the only first-session path, the `--session` SessionStart self-heal for resumes, and the `announce-capabilities.sh` "declared ≠ installed ≠ surfaced" canary. * `Claude Code on the web`: plugins are installed DECLARATIVELY by the platform at session start from the marketplace declared in `.claude/settings.json` (per the web docs' "what carries over" table) — so remove the overbuilt install machinery added in #162: the root `Makefile`/`make install-deps` Setup-script entrypoint, the three-mode engine, and every "the platform does not install enabledPlugins" claim. `install-deps.sh` is now a plain `CLAUDE_CODE_REMOTE`-gated SessionStart hook that provisions only non-plugin tooling (gh/codex CLIs, the project dev toolchain + Docker via `install-deps.local.sh`) plus a cheap idempotent `ensure_plugins` SELF-HEAL for the docs' "requires network access to reach the marketplace source" failure mode. The `cc-web-setup` skill, CONTRIBUTING.md, and announce-capabilities.sh are re-scoped to the declarative model; no Setup-script field and no manual per-environment step are required

### Fixed
* `Claude Code on the web`: install the declared `enabledPlugins` from `web-bootstrap.sh` (new `ensure_plugins`), reading the set straight from `.claude/settings.json`. The platform registers `extraKnownMarketplaces` at session start but does NOT install the enabled plugins from them (verified live on 2.1.185) — so after #160 removed the install machinery, a fresh cloud env had every marketplace registered yet zero plugins installed and no `/<plugin>:<skill>` commands. The install is idempotent (skips plugins already in `claude plugin list`) and non-fatal. `announce-capabilities.sh` now surfaces a one-time "web setup active — commit, plugins appear next session" note when a plugin was freshly installed, and its stale "platform installs plugins at session start" comments are corrected
* `.devcontainer`: drop podman-only `runArgs` (`--userns=keep-id`, `--security-opt=label=disable`) so `devcontainer up` starts under Docker as well as podman. Bind-mount uid alignment now relies on Dev Containers' `updateRemoteUserUID` (the container `node` user is synced to the host uid on start) instead of assuming the host runs as uid 1000; rootless podman users can re-add `--userns=keep-id`. `--cap-add=NET_ADMIN`/`NET_RAW` (needed by `init-firewall.sh`) are retained
* `cc-web-setup` skill: create the `web-bootstrap.sh` SessionStart log via `mktemp` under `umask 077` instead of a fixed `/tmp/rdl-web-bootstrap.log`, closing a symlink-truncation and concurrent-session race window on shared hosts
* `.claude/settings.json`: register the `claude-plugins-official` marketplace in `extraKnownMarketplaces` so the enabled `superpowers`, `gopls-lsp`, and `pr-review-toolkit` plugins resolve and install on Claude Code (web) — previously only `openai-codex` was declared, so those plugins' slash-commands/skills (e.g. `/test-driven-development`) never appeared
* `Claude Code on the web`: scope `.claude/settings.json` to **external dev-helper plugins** (`superpowers`, `gopls-lsp`, `pr-review-toolkit`, `codex`, `modern-go-guidelines`, `astral`, `worktrunk`) and their marketplaces, and remove the self-referential `rdl` marketplace + `rdl@rdl` meta-plugin from the web set — a session for developing this catalog should not install the catalog. Declared plugins install at session start from their (reachable) marketplace, so their `/<plugin>:<skill>` commands surface on the first session, the same path that gives dataops its `/superpowers:*` (no setup script / `make` required)
* `announce-capabilities.sh`: report **installed** plugins (cross-checked against `claude plugin list`), not merely the declared `enabledPlugins` from `settings.json` — verified-installed plugins show under "Enabled plugins (installed)", while any declared-but-not-installed plugin is now flagged with the `make cc-web-setup` remedy instead of being silently announced as present (falls back to the declared set when the `claude` CLI is unavailable)
* `cc-web-setup`: the `ensure_plugins` self-heal now refreshes the marketplace index (`claude plugin marketplace update <marketplace>`) and retries once when a `claude plugin install` fails — recovering the common cold-VM case where the marketplace is registered but its local index is stale (`claude plugin install` reports "Plugin not found in marketplace … your local copy may be out of date" and does not refresh the index itself). Previously the retry re-ran the same failing install against the same stale index and could not recover; the set only installed once the platform refreshed the index on a later session. The "Declared but NOT installed" note in `announce-capabilities.sh` and the self-heal warning now name the stale-index cause, not just an unreachable source. Adds `ensure_plugins` coverage (healthy-index, stale-index recovery, already-present no-op, unreachable) to `test-install-deps.sh`.
