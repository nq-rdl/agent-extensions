# R Package Development

This skill owns the everyday package workflow and this project's conventions.
For a specialist task, load the sibling skill in the `r` plugin (in Claude Code
it is invoked as `r:<leaf>`; Codex lists the leaf name):

| Task | Skill |
|---|---|
| Writing, organizing, or debugging testthat tests | `r:lib-testing` |
| User-facing errors, warnings, messages, progress with cli | `r:lib-cli` |
| Deprecating, superseding, or marking functions experimental | `r:lib-lifecycle` |
| CRAN submission, resubmission, or reviewer feedback | `r:lib-cran-extrachecks` |
| Async or parallel code with mirai | `r:lib-mirai` |
| A command-line app shipped in `exec/` | `r:lib-cli-app` |
| General R language questions outside a package | `r:expert` |

For a task that spans several ("add a function, test it, prepare for CRAN"),
start here and load the others as each step needs them.

## Scope

Edit only what the user asked for. Do not switch formatters, add
infrastructure (CI, pkgdown, licences), or bump versions unasked; suggest them
instead. When the user asked for a change, make it without asking again, then
run the checks below and report their results.

## Creating a package

```r
usethis::create_package("path/to/pkgname")
usethis::use_testthat(3)          # testthat 3rd edition
usethis::use_mit_license()        # or use_gpl3_license(), ...
usethis::use_readme_rmd()
usethis::use_news_md()
usethis::use_air()                # air.toml; usethis >= 3.2.0
usethis::use_github_action("check-standard")  # use_github_actions() was removed in usethis 3.2.0
```

Layout conventions: one logical unit per file in `R/`, named after its main
function (`R/fit_model.R` holds `fit_model()`); tests mirror it
(`tests/testthat/test-fit_model.R`). `man/` and `NAMESPACE` are generated by
roxygen2: never edit them by hand.

## The development loop

Run from a terminal with `Rscript -e "..."`:

```bash
Rscript -e "devtools::load_all()"                    # load source like library()
Rscript -e "devtools::document()"                    # regenerate man/ and NAMESPACE
Rscript -e "devtools::test()"                        # whole suite
Rscript -e "devtools::test(filter = '^fit_model')"   # tests/testthat/test-fit_model*.R
Rscript -e "devtools::test_active_file('R/fit_model.R', desc = 'handles NA input')"  # one test
Rscript -e "devtools::check()"                       # R CMD check: fix every ERROR, WARNING, NOTE
Rscript -e "pkgdown::check_pkgdown()"                # reference index complete (pkgdown sites)
```

Order for a change: edit → format → `document()` → `test()` → `check()` →
NEWS.md. After changing any roxygen comment, run `document()` before testing.
`devtools::check()` skips CRAN's incoming Title/Description checks by default;
before a CRAN release, load `r:lib-cran-extrachecks`.

## Formatting

Follow the project's existing configuration:

- `air.toml` or `.air.toml` present → `air format .` (or `air format R/file.R`).
- No air configuration → keep the project's convention (for example
  `styler::style_pkg()` when CI or contributors use styler).
- A new package created here gets air via `usethis::use_air()`.

Never switch a project from one formatter to another unless asked.

## Coding conventions

- Base pipe `|>` and `\(x)` lambdas (R >= 4.1); tidyverse style as the baseline.
- User-facing conditions with `cli::cli_abort()`/`cli_warn()`/`cli_inform()`
  rather than `stop()`/`warning()`/`message()`; see `r:lib-cli`.
- Dependencies: `usethis::use_package("pkg")` for Imports (needed at run
  time), `usethis::use_package("pkg", type = "Suggests")` for tests,
  examples, and vignettes only.

## Documentation with roxygen2

Every roxygen block that produces an Rd file (anything without `@noRd`) must
be complete, including `@returns`. CRAN reviewers ask for `\value` on exported
topics, including ones marked `@keywords internal`; `R CMD check` does not
report it.

```r
#' Fit a model to the data
#'
#' @param data A data frame containing the training data.
#' @param formula A formula specifying the model.
#' @returns A fitted model object of class `pkg_model`.
#' @export
#' @examples
#' fit_model(mtcars, mpg ~ wt)
fit_model <- function(data, formula) {
  # ...
}
```

- Small private helpers need no roxygen block; for internal notes that should
  not become Rd files, use `@noRd`.
- Wrap roxygen comments at 80 characters; use `@inheritParams` for shared
  parameters; set `Roxygen: list(markdown = TRUE)` in DESCRIPTION.
- When you add an exported topic to a package with a pkgdown site, add it to
  `_pkgdown.yml` and run `pkgdown::check_pkgdown()`.

## NEWS.md

`NEWS.md` is the user-facing changelog shown on CRAN and pkgdown.

1. One bullet per user-facing change; none for internal refactors, test-only
   changes, or small documentation fixes.
2. Describe the change from the user's point of view and cite the issue or PR
   in parentheses: `(#123)`.
3. A bullet may have several sentences but stays on **one line**; do not wrap
   it.
4. Put the function name first so the bullet is easy to scan.
5. Order bullets alphabetically by function name; bullets that name no
   function go first.

```markdown
# pkgname (development version)

* Fixed an issue where the package failed to load on R 4.2 (#61).
* `fit_model()` now supports a formula interface in addition to x/y syntax (#42).
* `predict()` gains a `type` argument for class probabilities (#55).
```

At release the heading becomes the version and date, for example
`# pkgname 1.2.0 (2026-04-04)`.

## DESCRIPTION essentials

```
Package: pkgname
Title: What the Package Does in Title Case
Version: 0.1.0
Authors@R: person("First", "Last", email = "first@example.com",
                  role = c("aut", "cre"))
Description: What the package does, in one paragraph of complete
    sentences. Indent continuation lines by four spaces.
License: MIT + file LICENSE
URL: https://github.com/org/pkgname, https://org.github.io/pkgname
BugReports: https://github.com/org/pkgname/issues
Encoding: UTF-8
Roxygen: list(markdown = TRUE)
Config/testthat/edition: 3
```

The Title and Description rules that CRAN enforces are in
`r:lib-cran-extrachecks`.
